## 3. ROBOFEST-COUPLED Components

*   **SimulationController.tsx**: This file contains the logic that mutates the Robot State (simulating driving, cutting logic, physics simulation). It imports globalCuttingNetwork and dispatches updateLocomotion, setTorch, etc. 
    **Action**: DO NOT MOVE. This file must remain exclusively in RoboFest. Senior does not perform simulation; it strictly visualizes data generated by RoboFest.

## 4. Pure Components

*   DeckDetails.tsx, DryDock.tsx, HullSurfaceDetails.tsx, IndustrialMaterial.tsx, Magnets.tsx, SurfaceNavigationTest.tsx, TestShipCameraController.tsx.
*   **Why they are safe**: These files exclusively import from Three.js, React, R3F, or pure static config files (shipConfig.ts). They perform no network IO, handle no business logic, and mutate no stores. They are purely mathematical/visual.

## 5. Required Extraction Schemas

### A. Minimum TwinState Schema
The minimum interface that will replace all Zustand hooks in the extracted package:
`	ypescript
export interface TwinState {
  position: { x: number; y: number; z: number };
  arm: { yPosition: number; xExtension: number };
  torch: { enabled: boolean };
  electromagnet: { enabled: boolean };
  trackOffset: number;
  fifthCableLength: number;
  cameraTarget: 'robot' | 'cut' | 'ship' | 'free' | 'starboard' | 'port' | 'front' | 'rear';
  cameraFocusTrigger: number;
  uiMode: 'debug' | 'presentation';
  xRayMode: boolean;
  activeCutPath: Array<{x: number, y: number}>;
  completedCuts: Array<{ path: Array<{x: number, y: number}>, isClosed: boolean }>;
}
`

### B. Configuration Schema
The library relies on two static configuration files which must be extracted alongside it:
- lib/geometry/shipConfig.ts
- lib/robotConfig.ts

### D. NPM Dependencies
The extracted reusable component package, and Senior, must install:
- 	hree
- @react-three/fiber
- @react-three/drei
- 	hree-stdlib

### E. CSS/Global Styles
- .digital-twin-container (typically defined in globals.css). It simply requires width: 100%, height: 100%.

### F. Browser APIs Required
- WebGL2 context (handled via Canvas). No custom DOM manipulation.

### G. Server-Side Dependencies
- **NONE**. The extraction is 100% client-side rendering ('use client').

### H. Hidden Coupling Risks
- Asset URLs (e.g., /models/...) are hardcoded. If the extraction becomes an NPM package, those static files must be either bundled into the package or explicitly hoisted to Senior's /public folder.
- lib/geometry/ProceduralShipSurface.ts and lib/materials/useShipMaterials.ts are pure computational/Three.js utilities and must also be extracted.

## 6. Exact Recommended Extraction Boundary
1. Create a workspace package: packages/digital-twin.
2. Move src/components/DigitalTwin and necessary lib/geometry into it.
3. Strip Zustand out of digital-twin; introduce TwinContext.
4. In RoboFest: <TwinProvider state={useRobotStore()}>\n  <DigitalTwin />\n</TwinProvider>.
5. In Senior: <TwinProvider state={parsedSseState}>\n  <DigitalTwin />\n</TwinProvider>.
